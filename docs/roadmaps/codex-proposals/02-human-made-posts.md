## Verified starting point

Posts and replies already accept human-written captions, public links and up to four owned photos. The Log has a capable Square editor for an image made from a chosen photo, text, shapes and drawing, as well as a separate 15-second voice-note recorder. The shared audio player already handles compact playback. These are distinct surfaces with different privacy and storage rules.

## Founder decisions to preserve

Profiles remain human-authored. New video uploads are unavailable because each person has a 64 MB storage allowance; linked video remains valid. Log media belongs to a specific hangout and is private or explicitly shared. This proposal does not reuse a Log file in a Post or pull a private memory into public content. It does not ask an Agent to manufacture someone's public voice.

## Codex hypothesis

New Drugs could make public posting more expressive by offering the existing visual editor as an **optional way to make a Post image**. A person starts from a blank square or a newly chosen image, places human-written text or marks, previews the result, and explicitly adds that one image to the Post draft. They can still post ordinary uncropped photos. The editor should not become the default Post composer or a required step.

This would use a large piece of shipped creative work outside Log while keeping the authorship decision with the person. It is a different future from an AI-generated feed.

## If the founder selects it

1. Extract only the reusable editing/rendering behavior from [Square](../../../src/SquareEditor.tsx). Keep a distinct Post entry path so the Log attachment lifecycle cannot be crossed accidentally. The person's current Post caption, links, photos and scroll survive entering, cancelling and saving the editor.
2. Upload the approved output as a new owned Post photo under the existing quota and four-photo limit. A cancelled or failed attempt cannot leave an orphan upload. Post/reply review shows the final pixels before publishing. External CLI/MCP writers can still supply their own images through the existing upload and post operations.
3. Preserve Square's separate desktop and touch interactions, including gesture placement and a stable mobile preview. Check the complete Post composer at narrow widths rather than assuming the Log panel geometry transfers.
4. Consider optional **human-written alt text** for each public photo. It should be displayed to assistive technology and, if indexed later, remain explicitly authored public text. It must never be inferred from a person's appearance or quietly generated by a model. The current [Post photo renderer](../../../src/PostPhotos.tsx) merits inspection here because filenames are a weak description.

### A separate possible extension: short voice posts

A bounded voice clip could use the Log recorder's capture interaction and the shared player, but public audio needs its own upload purpose, moderation, accessibility/transcript choice, playback policy, search decision and quota handling. It should be reviewed independently after the visual-post question, not bundled into a first build. Audio is not a workaround for the no-video-upload decision.

## What would make this a poor choice

If a second editor makes posting slower or harder, ordinary photos and text should remain the center. If people mainly want to share moments as they are, Square belongs in Log. The feature should be judged by whether real people choose to make and share something with it, not by how much generated media it adds to a feed.
