# Calls and Talk

Both stages have two live media surfaces. Private one-to-one video starts from an accepted friend's DM. Starting a call creates a waiting card and keeps the person in the app. Answering opens the stage for both people, including the caller after navigating away from the DM. The top-right Settings control temporarily shows the bold username followed by regular Video call text (Video on mobile/touch), with a thin circular indicator on the right and no icon inside it. Connected calls retain their DM card and show elapsed duration when ended. Quiet ringback and incoming tones play when the browser permits audio. The full-screen stage uses `../pair-video`'s Squircle tiles, black field, mobile stack / desktop pair, local mic/camera/end controls and audio visualizer. The remote video fills its tile with edge cropping. Microphone and camera permission are requested together when possible.

Public live-audio Talk spaces belong under Posts. The host, speaker and listener model follows Twitter Spaces. Opening a talk space requires a human-written title and accepts an optional description. The creator joins immediately with the microphone on. An active space stays connected across app navigation in a compact bottom panel below the current main panel, including the Agent tab. Expanding it shows speakers, host speaking requests, listeners, sharing and moderation. The compact row shows overlapping speaker photos before the speaking count, followed by listener photos before the listening count only when listeners are present. Only muted speakers have a mic mark; a pending speaking request fills the listener's hand icon. New host requests and speaker approval use separate short, quiet tones where browser audio is permitted. The Info control reveals only the description in an inline panel. Public semantic search indexes the live title and any description, never participant profiles or tags. There are no recordings, video tracks, or automatic Log entries.

Each stage has a separate self-hosted LiveKit 1.13.7 service on the current host. The dev service is `newdrugs-livekit-dev.service`, with private config and credentials at `/etc/newdrugs/livekit-dev.yaml`, `/etc/newdrugs/livekit-dev.keys` and `/etc/newdrugs/dev.env`. Nginx proxies `https://dev.druggie.org/rtc` to port 7880. Dev media uses ICE/TCP 7881, ICE/UDP 7882, TURN/UDP 3478 and TURN/TLS 5349. The production service is `newdrugs-livekit-prod.service`, with separate credentials in `/etc/newdrugs/livekit-prod.keys` and `/etc/newdrugs/prod.env` and config at `/etc/newdrugs/livekit-prod.yaml`. Nginx proxies `https://druggie.org/rtc` to port 7890. Production media uses ICE/TCP 7891, ICE/UDP 7892, TURN/UDP 3479 and TURN/TLS 5350. Both use the `druggie.org` certificate, and separate renewal hooks restart each media service. Set `LIVEKIT_PUBLIC_URL` to the origin only (`wss://dev.druggie.org` or `wss://druggie.org`); the browser SDK appends `/rtc`. An initial production setting with `/rtc` in this base URL made requests hit `/rtc/rtc` and fail. The corrected production origin passed a public validation request and authenticated WebSocket join after an API/worker restart. The production service and v0.35.1 app release were activated October 1, 2026. Config, credentials and pre-release environment/nginx backups remain only on the host.

The app backend checks current connection, block, suspension, Talk space status and removal state before issuing a two-minute room token. Private calls admit only the two accepted friends. Talk listeners receive subscribe-only permission; the host and approved speakers may publish microphone audio only. A transaction-bound media-effect queue closes rooms and updates participant permissions after app state changes, retrying service failures. LiveKit webhooks are signed. A host browser refresh does not end the space on `participant_left`; explicit End or `room_finished` closes it. LiveKit keeps a room open for 90 seconds after the last participant leaves, allowing a tab reload to rejoin. The browser stores the active space ID and mic state in account-scoped session storage for this purpose. Talk spaces are public to saved accounts, with no inferred topic from the people present.

Browse cards and preview pages count connected participants, not everyone with speaking permission. Signed join/leave webhooks update the indexed Mongo presence projection, with SID fencing so an old leave cannot remove a rejoined participant. The worker reconciles five live rooms per pass against LiveKit every ten seconds, repairing missed webhooks and rooms that were already open during deployment. This is a bounded repair path, not a measured high-capacity guarantee.

Earlier cloud dev transport QA used temporary accounts and cleaned them afterward. Two browser sessions exchanged video and audio. A host and listener exchanged audio, a request to speak was approved, and semantic search found a live description. A forced relay-only browser session published microphone audio, verifying TURN media rather than merely a TLS handshake. The later call-flow, Talk-panel and refresh changes passed targeted unit/integration checks and desktop localhost visual review. Production activation passed app API and worker health, a public asset byte comparison, an authenticated LiveKit room-service call, external TCP media and TURN TLS reachability, and a TURN UDP STUN response. Production two-person media, media over UDP, physical-phone behavior, chime audibility and concurrent-user capacity have not been measured. The single-node host and a 100-participant room setting are safety bounds, not a capacity claim.
