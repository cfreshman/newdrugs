# Calls and Spaces

Cloud dev now has two live media surfaces. Private one-to-one video starts from an accepted friend's DM. The call is a real card in the message timeline with waiting, connected and ended states. Starting or joining opens a full-screen stage based closely on the read-only `../pair-video` reference: black background, equal square videos, stacked on mobile and side by side on desktop, local mic/camera/end controls, remote waiting state and audio visualizer. Ending closes the stage and leaves the card in the DM. An incoming call raises an in-app notification and banner.

Public live-audio Spaces belong under Posts. The room follows Twitter Spaces' host, speaker and listener sections, circular people, speaking indication and bottom mic/request/share controls. The host reviews individual requests to speak and can revoke a microphone or remove someone from that Space. A Space needs a title and human-written description. Public semantic search indexes only the live description, never participant profiles or tags. There are no recordings, video tracks, or automatic Log entries.

Both use self-hosted LiveKit 1.13.7 on the current dev host. Its selective forwarding server avoids a listener mesh. The dev service is `newdrugs-livekit-dev.service`, with a private config at `/etc/newdrugs/livekit-dev.yaml` and credentials in `/etc/newdrugs/livekit-dev.keys` and `/etc/newdrugs/dev.env`. Nginx proxies `https://dev.druggie.org/rtc` WebSocket signaling to loopback port 7880. Media uses ICE/UDP 7882, ICE/TCP 7881, TURN/UDP 3478 and TURN/TLS 5349 with the existing dev-domain certificate. A certificate renewal hook restarts the media service. Production has no calling service authorization or app release yet.

The app backend checks current connection, block, suspension, Space status and removal state before issuing a two-minute room token. Private calls admit only the two accepted friends. Space listeners receive subscribe-only permission; the host and approved speakers may publish microphone audio only. A transaction-bound media-effect queue closes rooms and updates participant permissions after app state changes, retrying service failures. LiveKit webhooks are signed and update calls and Spaces when participants leave. Spaces are public to saved accounts, with no inferred topic from the people present.

Cloud dev QA used temporary accounts and cleaned them afterward. Two browser sessions exchanged video and audio, ended both stages, and retained the ended DM card. A host and listener exchanged audio, a request to speak was approved, and semantic search found the Space by its description. A forced relay-only browser session published microphone audio, verifying TURN media rather than merely a TLS handshake. Mobile and desktop stage geometry and mobile Space layout were inspected. Physical-phone, restrictive-network and concurrent-user capacity have not been measured. The current single-node media host and a 100-participant room setting are safety bounds, not a capacity claim.

References: [LiveKit self-hosting](https://docs.livekit.io/transport/self-hosting/deployment/), [ports](https://docs.livekit.io/transport/self-hosting/ports-firewall/), [access grants](https://docs.livekit.io/frontends/reference/tokens-grants/), and [X Spaces](https://help.x.com/en/using-x/spaces).
